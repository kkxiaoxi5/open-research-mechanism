# Open Research Mechanism（オープンリサーチ機構フレームワーク）

[简体中文](README.md) | [English](README.en.md) | **日本語**

> 言語：ドキュメント、プロンプト、コンソール UI は英語（日本語版を併置、docs/ja/）；中国語は README にのみ残しています。

> 複数の AI エージェントが**協働して新しい知識を創造する**ための運用機構。
> 本リポジトリが公開するのは**機構のみ**：役割の分け方、タスクの流し方、
> 証拠の数え方、漂移せずに拡張する方法。
> 具体領域の内容（データ・戦略・結論）は含まない——機構と内容の分離が、
> このフレームワークの第一原則である。

---

## 解決する問題

単一の AI セッションが研究を行うと、自然に四つの失敗モードへ滑っていく
（本機構はそれらを塞ぐために設計された）:

1. **タスクの漂移** — 作業が当初の問題から少しずつずれていく。
2. **繰り返し労働** — すでに知っていることを「検証」し直す。知っているかどうかを、まず自分に問わない。
3. **中途放棄／未検証の通過** — 難しくなると諦める。少し見て大丈夫そうだからと検証を省き、バグを出す。
4. **人を増やしても速くならない** — 人手が増えても提出が増えるだけで、情報伝達と審査がボトルネックになり、スループットはむしろ下がる。

## 中核のアイデア

- **記憶ではなく知能を使う**：エージェントの価値は、新しい道具・理論・解釈を創ることにある。訓練データの既知の結論の再生ではない。
- **行動の前に、立つ規則**：どの結論も、データを見る前に事前予測と判定基準を書く。規則がなければ賭けない。
- **内容より機構が先**：「どう運用するか」を先に固めて版管理し、検収してから、具体的な研究を始める。
- **すべて検証可能に**：タスクには認領記録、交付には固定形式、結論には証拠等級があり、失敗は完全に残る。

## クローンして参考実装を動かす

```bash
git clone https://github.com/kkxiaoxi5/open-research-mechanism.git
cd open-research-mechanism/agent
./deploy.sh            # Linux/macOS（Windows は .\deploy.ps1、サーバーは docker compose up -d）
```

`http://127.0.0.1:8765` を開くと互動コンソール（決定待ち / 認領ボード /
チケット / メンバー / 動態）。依存ゼロ、Python ≥ 3.11 のみ。デモ後端は
キー不要、実モデル接続は `agent/README.md` を参照。

## クイックスタート

1. `docs/01-philosophy.md` を読み、「根本要求」を自分のプロジェクト版に書き換えて独立ページにする。
2. `docs/02-architecture.md` に従い、各セッションに一意の名前を付け、名簿に登記する。
3. `templates/claim-card.md` で最初のカードを出し、交付には `templates/delivery-block.md` を必須とする。
4. 審査と著者を分離する：非著者の復核を通るまで「受領済み」とは数えない。
5. 毎日一頁：冒頭で「根本要求」と照合し、今日どの判断が変わったかを書く。

## ではないもの

- 特定領域の戦略ライブラリやデータセットではない（内容は自分の非公開リポジトリに置くこと）。
- プロンプト集ではない：プロンプトは機構の担体の一つにすぎず、本リポジトリが公開するのは構造と規則である。
- 全自動のブラックボックスではない：重要な判断（立項、証拠の格上げ、結果の使用）には明示的な人間の決定点を残す。
