# mechanism-agent —— 機構の実行可能なコード

[简体中文](README.zh-CN.md) | [English](README.md) | **日本語**

本リポジトリの文書が記述する「漂移せず、止まらず、自らを欺かない」
多エージェント研究の機構を、そのまま小さな依存ゼロの参考実装にしたもの
（Python ≥ 3.11、標準ライブラリのみ）。単一マシン——イントラネット内の
マシンを含む——でエンドツーエンドに動く。

## 中身

| モジュール | 実装している機構の部品 |
|---|---|
| `board.py` | 追記専用の認領ボード（JSONL＋ファイルロック）。葉の関単は **証成／証否／拆小** の三態のみ——「判別不能」は書き込み時点で拒否される。行き詰まりには説明が必須で、別角度の子葉が派生する。 |
| `agents.py` | 作業エージェント（答えを提案）と復核エージェント（事前登録された既知答案チェッカーで独立に再計算）。著者は自分の葉を絶対に閉じられない——規約ではなくコードによる強制。 |
| `orchestrator.py` | ウェイクアップ一巡：期限切れリースと行き詰まり葉の照合 → 派遣 → 復核 → スナップショット書き出し。 |
| `backend.py` | 差し替え可能なモデルバックエンド：決定論的なモック（キーなしでデモが走る）と、OpenAI 互換クライアント（公網・内網どちらのモデルにも接続可）。 |
| `tracker.py` | 人間規模のチケット（タスク／質問／決定、「決定待ち」キュー付き）と**スナップショット書き出し**——チケットの状態がサービスの中だけに住むことはない。 |
| `webapp.py` | 互動コンソール（ユーザーの操作面）：決定待ちキュー、認領ボード、チケット、メンバー、動態の五ビューに加え、葉を開く、票据を決定する、メンバーへメッセージ、叫醒一輪の実行ができる。全操作はエージェントと同じ Board/Tickets 規則を通して書き込まれ、状態ファイルへの直書きの抜け道はない。`dashboard.py` は静的スナップショット描画として残る。 |
| `skills/` + `skills.py` | 捆绑された七つのプレイブック（葉の分解、既知答案テスト、反例ハンティング、証明復核、形式化、証拠記賬、チケット工作流）。役割ごとに各エージェントのプロンプトへ読み込まれる——仕事の習慣が機械と一緒に出荷される。`skills` コマンドで一覧できる。 |

## デモを動かす（キー不要、1 分）

```bash
cd agent
PYTHONPATH=src python -m mechanism_agent --home ./mech-state init
PYTHONPATH=src python -m mechanism_agent --home ./mech-state seed-demo
PYTHONPATH=src python -m mechanism_agent --home ./mech-state run
PYTHONPATH=src python -m mechanism_agent --home ./mech-state serve   # http://127.0.0.1:8765

ワンクリック配備：

```bash
./deploy.sh            # Linux/macOS：初期化 + シード + コンソール起動
.\deploy.ps1           # Windows PowerShell
docker compose up -d   # サーバー配備（状態は volume に保存）
```
```

デモは三枚の葉を植え、一巡で三つの結末すべてを通す：一つは正解で
（**証成**）、一つは誤答で復核側の再計算に捕まり（**証否**）、
一つは原題のままでは答えられず（**拆小**：判定可能な子葉二枚に分かれ、
やがて証成で閉じる）。

テスト：`PYTHONPATH=src python -m unittest discover -s tests -v`

## 実モデルへの接続

`MECH_AGENT_BASE_URL`、`MECH_AGENT_API_KEY`、`MECH_AGENT_MODEL` を
任意の OpenAI 互換エンドポイント（内網のモデルサーバでよい）に向ければ
`run` がそれを使う。他の部品——認領ボード、チケット、スナップショット、
ダッシュボード——は一切変わらない：
**内容と鍵は自分のマシンに残り、共有されるのは機構だけである。**

## v0.1 の範囲

意図的に小さく保つ：単一マシン、分散なし、権限システムなし
（自社内網側のアクセス制御の背後に置く前提）。小さくないのは
肝心な部分だけ：関単の規則、著者／復核の分離、スナップショット契約は、
フレームワーク文書の本物の規則であり、コードが強制する。
