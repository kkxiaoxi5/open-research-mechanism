# リーフ分割（chaiye）

リーフとは、その結果を、ワーカー自身の推論に依存しないチェッカーで採点できる最小の作業単位である。ある部分をどう採点するかを言えないなら、それはまだリーフではない。

## 手順

1. **親の主張を一文で述べる**。量子化子と定義域を明示すること。「分割できない」問題のほとんどは、単に主張が述べられていないだけである。
2. **継ぎ目を見つける**：場合分け（符号・大きさ・偶奇・レジームによる）、証明に必要な補題、数値的にチェックできる計算、そして主張が最も死にやすい境界ケース。
3. **1リーフにつき、採点可能な問いは1つ。** 各リーフには、問い、チェッカー（登録済みの名前＋引数）、そして各結果が親にとって何を意味するかを持たせる。
4. **リーフ同士は衝突してはならない**：2つのリーフが同じ対象を変更できてはならない。重なりはクレームカードに宣言すること。宣言できないなら、その分割は間違っている。
5. **殺傷力の高い順に並べる**：親を最も反証しそうなリーフを最初に置く。最も簡単な部分から始める分割は、先延ばしであって分解ではない。

## ルール

- 「split（分割）」で戻ってきたリーフが2回続いたら、コーディネーターが再検討する。疑うべきはワーカーではなく問題文のほうである。
- 分割そのものが1つの交付物である：分割（子リーフ＋根拠）は、どの子にも着手する前にボードに載せる。
- 並行して走らせられるワーカーの数＋レビューキューの2件分を超えて分割してはならない。余分なリーフは在庫であり、在庫は陳腐化を隠す。
