# 形式化

機械がチェックした論証は、語り直しによって黙って弱められることがなく、セッションが終わっても漂わず、他のどのセッションでも数分で再検証できる。形式化とは、1つのセッションの洞察がチームの恒久的な資産になる方法である。

## 何を形式化するか（この順序で）

1. **まず荷重のかかる補題**——見出しの結果ではなく、他の証明がその上に立つステップ。形式化された補題は無料で再利用できる。形式化された見出しはトロフィーである。
2. **手で「再証明」されたことが複数回ある主張はすべて。** 2回目の再証明が合図である：再導出のコストを永遠に払い続ける代わりに、形式化のコストを一度だけ払う。
3. **チェッカーにとって決定的な恒等式**——既知答案チェッカーが依拠する公式。チェッカーが間違っていれば、それが出した判定はすべて疑わしい。その土台には最も強い形のチェックを与える。

## 手順

- 証明を書く*前に*、形式体系の中で主張を述べる。形式化の失敗の半分は、非形式的な主張が曖昧だったという発見である。その発見自体が交付物である：曖昧さを親リーフの分割として報告する。
- 形式的な成果物と非形式的なテキストを並べて置き、荷重のかかるステップについては行レベルの対応を付ける。論証へ対応づけられない形式証明は、誰も納得させない。
- 失敗した形式化の試みは、どこで行き詰まったかとともに記録される。「機械がステップ4を拒否した」は非形式的な論証についての正確な情報であり、捨てずにレビューコメントとして著者へ送り返す。

## 正直な限界

形式化が検証するのは、その証明がその主張文から従うことである——その主張文が意図したことを言っているかどうかではなく、前提が現実の世界で成り立つかどうかでもない。主張文のレビューは人間／レビュアーの仕事として残り（proof-review のステップ1を参照）、前提は証拠台帳の中に残る。
