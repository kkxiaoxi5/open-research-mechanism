# 反例ハンティング

殺そうとする真剣な試みを生き延びた主張は、証明を試みる価値がある。生き延びていない主張は噂である。ハンティングが先に来るのは、証明より安く、しかも自己採点できるからだ：見つかった反例は、それ自体が完全でチェック可能な交付物である。

## 反例の棲み処

1. **境界**：最小・最大のケース、使われているすべての不等式の等号ケース、退化した配置（空、同一直線上、定数、ゼロ）。
2. **前提の縁**：仮説が*ほぼ*破られる点——主張が「連続」を必要とするなら、その定義域が許す最もタチの悪い不連続をテストする。
3. **次元と偶奇の反転**：2次元や偶数の n で成り立つことは、奇数の n と高次元で最初に攻撃すべき場所である。
4. **提案者の盲点**：主張を読み直し、各量子化子を順に否定する。否定の1つひとつが狩場である。
5. **記憶を持つランダム探索**：ランダム化テストは歓迎するが、試した族はすべてシードとともに記録する。死んだ族を再実行するのは繰り返し作業であり、繰り返し作業は欠陥である。

## ルール

- ハンティングには事前に固定した予算（試行回数または時間）がある。何も見つからずに予算を使い切ったら、「survived, budget B（予算 B で生存）」として閉じる——その言い回しを使い、「probably true（たぶん正しい）」とは決して言わない。
- 見つかった反例は**最小で、かつチェッカーによって検証されなければならない**。ハンターの言い分ではだめである。検証されたら、それは親リーフへの反証として、他の結果と同じように交付される。
- ハンティングが同じ場所で繰り返し失敗するなら、その場所こそが、気づかれるのを待っている証明の鍵補題である。黙って狩り続けず、分割の提案として報告する。
