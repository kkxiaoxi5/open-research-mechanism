# 証明レビュー

レビュアーは校正者ではない。レビュアーの仕事は、最も安い場所から順に、その論証を失敗させようとすることであり、リーフを proven（証明済み）／ refuted（反証済み）／ split（分割）のいずれかで閉じることである。

## 手順

1. **まず対題（duiti）**：自分の第一行に、リーフが開かれたときの主張そのものを言い直す（交付物からではなく、クレームカードからコピーする）。交付物が別の主張——より弱いもの、特殊ケース、逆——を証明しているなら、それは*この*リーフへの反証である。もう一方の結果がどれほど見事でも関係ない。
2. **真ん中より先に両端をチェックする**：主張の境界ケースと、最終ステップでの補題の使い方を検証する。壊れた証明のほとんどは継ぎ目で壊れている。
3. **荷重のかかる数値はすべて再計算する**。リーフのチェッカーで。論証全体がその上に立つ単一の数値は、2回、できれば2つの異なる経路で再計算する。
4. **隠れた前提を狩る**：証明が使っているのに主張の前提にない事実をすべてリストアップする（「clearly」「obviously」「standard」が目印）。リストにない前提は、閉じられたリーフへの引用を得るか、新しいリーフになるかのどちらかである。
5. **変異パス**：仮説を1つずつ頭の中で壊し、証明のどこがそれに気づくかを問う。どの仮説破壊にも揺るがないステップは装飾であり、装飾は隙間を隠す。

## 閉じ方のルール

- **Proven（証明済み）**：荷重のかかるステップをすべて再導出するかチェッカーで検証し、自分の反例パス（最低でも境界）でも何も見つからなかった。
- **Refuted（反証済み）**：失敗するケース、あるいは従わない正確なステップを提示する。「Seems wrong（間違っていそう）」は判定ではない。
- **Split（分割）**：名前の挙がった不足補題を除けば論証は健全である。その補題は、自身のチェッカーを持つ子リーフになる。
- 自分が著者のリーフを閉じてはならず、結果が望まれているからといって判定を甘くしてはならない。圧力がかかったらそれを記録する。それもまたデータである。
