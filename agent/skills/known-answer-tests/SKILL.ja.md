# 既知答案テスト

事前に名前を指定されたチェッカーなしにリーフは開かれず、答えが実行前に固定されたテストに合格するまで、ツールは受理されない。

## チェッカーの設計

1. **チェッカーは再計算する。再読は決してしない。** リーフが宣言した引数を受け取り、第一原理から判定を生み出す（閉形式、小さいケースでの総当たり、独立した別手法）。ワーカーの導出をパースして判定することは決してしない。
2. **答えが存在する前にチェッカーを固定する。** チェッカーの名前と引数は、開く時点でクレームカードに書かれる。答えを見たあとでチェッカーを変えることは、新しい試行として記録される。
3. **ネガティブコントロールを含める**：意図的に間違えた答えは、チェッカーで不合格にならなければならない。何も落としたことのないチェッカーは、壊れているとみなす。
4. **チェッカー自身の限界を述べる**：正確に判定できる引数の範囲、近似になる範囲（とその許容誤差）、そして飽和して推測ではなく拒否しなければならない範囲。

## 合成世界

現実がグラウンドトゥルースを供給できないときは、メカニズムを自分で書き、したがって答えが分かっている小さな世界を作る：生成器のパラメータが答え合わせの鍵である。ルール：

- 合成世界で測った結果は**較正（キャリブレーション）**であり、現実世界についての証拠では決してない。「既知の条件のもとでこの手法が正しく／正しくなく振る舞う」と引用するときにだけ使う。
- すべての合成世界にはシードと生成器のコードが付属し、どのセッションでもビット単位で再実行できる。
- 現象を示す最小の世界を好むこと。手で説明できない世界は、何の採点にも使えない。
