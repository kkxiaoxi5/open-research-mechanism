# 05 · 研究の不確実性：新しい数学ツールを発明する方法

本フレームワークの出発点は一つの判断である：**真に不確実な対象に対しては、古典的確率論の機械はしばしば課題に合っていない。** 未来は一度だけ実現する。「確率」そのものは世界についての仮説であり、世界に付属する属性ではない。標本が天然に少なく、メカニズムが変わり、観察者が系の内側にいるとき、歴史的な頻度を未来の確率分布とみなすことは、仮説を事実と取り違えることである。本章は、この種の問題に直面したとき、既成品を適用するのではなく、新しい数学ツールを体系的に**発明**する方法を述べる。

## まず境界を証明し、それから方法を探す

ツールを発明する第一歩は、構成ではなく境界画定である：

1. **識別可能性が先**：まず「手元の情報で、この問題は最大どこまで答えられるか」を問う。明記されたモデルクラスの内部で、観測的に等価な反例を構成する：二つのメカニズムが完全に同一の観測可能な分布を生むなら、それらは区別できない——これは失敗ではなく、数か月分の誤った道を節約する定理である。
2. **不足している情報を名指しする**：識別できないときは、「分けるにはどの類の情報が不足しているか」を明記する（例：行為主体の制約状態、メカニズム切替の時点）。不足に名前が付くと、それは自動的にデータカードか新しい命題カードになる。
3. **否定的結果は資産**：「分けられない」と証明できたことと「分けられる」と証明できたことは、同等に記録し、同等に引用する。引用時にはモデルクラスの境界を必ず付ける。

## ツール発明のパイプライン

```
実際の問題における詰まり点
  → 最小の合成世界（偽市場／偽データ生成器：メカニズムは固定で書き込み、答えは既知）
  → 合成世界の中で推論する：何が証明でき、どこで失効するか（まず手書きの論証、形式化は後）
  → 既知答えテスト＋壊したら必ず失敗するテスト
  → 実際の問題に戻る：一つの判断が変わって初めて、ツールが成立したことになる
  → ツールカードを登記する（原理／境界／失効情形）
```

- **合成世界は実験室であって試験場ではない**：合成世界で得られた効果量は設定値であり、現実の推定として引用しては決してならない（`04-evidence.md` の証拠の層を参照）。
- **形式化は増幅器**：論証を機械で検査可能な形（定理証明器、性質テスト）に書くことで、一つのセッションの洞察を他のセッションが数分で審査できるようになる——これが「人を増やせば加速する」の数学ラインにおける実現方法である：一人が提案し、多数が並行して検証と反例探しを行う。
- **大規模な探索**：候補ツール／候補命題はまず一括生成し、次に反例で淘汰する。淘汰の記録は完全に保持する（何を選び、なぜ死んだか）。グローバル試行カウントと合わせて記録する。

## 研究の不確実性に関する作業仮説（プロジェクトごとに差替可能）

- 「不確実性」そのものを研究対象とする：分布が漂移するときは、分布が固定されているふりをせず、まず**漂移の構造**（何が速く変わり、何がゆっくり変わり、何に記憶があるか）を研究する。
- 標本の少ない大きな事象については、頻度から有意性を無理に作らず、先験とメカニズムの推論で重みを定める。結論は p 値ではなく、「どの決定が変わるか、どれだけの建玉で」という形で表す。
- 予測の質は**採点ルール**で測る（ツールラインの乙類を参照）。口座の成績、統計的証拠、予測の質の三者は分けて報告し、単一の「倍数」で互いに成り代わることを禁じる。
- すべてのツールは**失効条件**を書かなければならない：どのような観測が現れたら、そのツールの言うことが無効になるか。失効条件のないツールはツールプールに入れてはならない。

## 証拠規律との関係

本章は「どう造るか」を担い、`04-evidence.md` は「造ったものが何点に当たるか」を担う。発明の段階では連続的な探索を奨励し、「一度だけ走らせる」は撤廃する。ただし探索の結果は確認として書き上げず、選択と失敗はすべて登記する——自由は探索の層に、規律は主張の層に置く。
