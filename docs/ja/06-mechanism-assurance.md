# 06 · メカニズムの自己保証：途中で止まらず、静かに変質しない

メカニズムにとって最大のリスクは反対されることではなく、**回っているうちに止まってしまうこと、あるいは静かに味が変わってしまうこと**を、誰も気づかないことである。本章は、メカニズムが自らをどう保証するかを述べる：活性、正しさ、回復、防腐の四つである。

## 活性（Liveness）：止まったら誰かが知ること

- **定時起床**：調整者は固定のリズムで起こされる（「暇なときに見る」ではない）。起床のたびにまず読み取り専用のチェッカーを走らせ、それから業務を処理する。チェッカーが答えるのは三つの問いだけである：誰の成果物が受領漏れか、誰の申込が期限切れか、どの表が更新されず古くなっているか。
- **ハートビートと唯一の書き手**：継続プロセスの類（データの着地、記帳、監視）ごとに唯一の書き手を置き、書き込みにはタイムスタンプを付ける。約定の間隔を超えて新しいタイムスタンプがない = そのプロセスは死んでいる。「今日はデータがない」としてではなく、事故として扱う。
- **受領漏れの検出**：メッセージの「既読」と成果物の「受領済み」の間に独立した照合を挟む（チェッカーが状態表とコミット履歴を突き合わせる）。受領漏れは次回の起床時に必ず拾い上げられる。

## 正しさ（Correctness）：間違ったら捕まえられること

- **単一の真源＋ロック**：原話、タスク状態、証拠台帳は、それぞれ真源が一つだけ。書き込みは統一された入口を通し、ロックを掛ける。入口を迂回してファイルを直接変更することは禁じる。
- **変異テストはメカニズム自体にも適用する**：主要ルールに対して定期的に変異を行う——一か所をわざと間違えて書き（必須項目を一つ落とす、閾値を一つ変える）、ゲートが捕まえられるかを見る。捕まえられないゲートは存在しないものとして数える。
- **ゲートの前置**：提出前に自動で検証する（必須項目、事前の検出力ファイルの存在、口径の表示）。不合格はその場で差し戻し、事後の審査で拾うことに頼らない。
- **作者は自己審査しない**はメカニズムの変更にも適用される：ルールを変えた者は、新しいルールの発効を単独で宣言できない。ルールの変更は痕跡を残す（誰が、いつ、どの原話／決議に基づいてか）。出所のないルールは発効しない。

## 回復（Recovery）：壊れても引き継げること

提出と引継ぎは**冪等**に設計する。六種の故障それぞれに、再実行可能なテストが必要である：

1. 同じ成果物が重複して提出される → 二重に記録しない。
2. 読み取りの瞬間に新しい返信が届く → 失わず、読み位置もずれない。
3. 複数人に通知され、一人が事項を閉じる → 他の人の未処理が正しく失効する。
4. 「受領」後に実行者が停滞する → チェッカーが期限切れを警告し、再割当てできる。
5. 古いインスタンスが遅れて提出する → 版で判定し、新しい版の結論を上書きしない。
6. v1 の提出が v2 の提出より後に届く → 状態表は版を正とし、後退しない。

- **引継ぎ演習**：新しいセッションが、引継ぎページと真源ファイルだけを頼りに、主要な数字を再現し、作業を引き継げなければならない。演習に通らなければ、知識がまだどこかのセッションに閉じ込められているということであり、アーキテクチャの欠陥として扱う。
- **バックアップの検収**：ローカルとリモートの HEAD が一致することを一つずつ照合して初めてバックアップ完了とする。「別のディスクにコピーした」はバックアップではない。

## 防腐（Anti-decay）：長くても変質しないこと

- **根本要求への定期照合**：毎日の一ページでまず照合し、毎週全体を照合する。照合の結論は「適合／ドリフト（どの条項かを指す）」のみとし、ドリフト項目は次ラウンドのクレームボードに入れる。
- **縮退モードを明記する**：リソース（枠、計算資源、審査の人力）が凍結されたときは、停滞ではなく、あらかじめ定めた経路で縮退する——どの仕事を続け、どの仕事を止めるか、凍結中に誰を起こしてはならないか——をすべて事前に状態表に書いておく。凍結が解けたら、まず状態を読み直してから仕事を割り当てる。
- **引用の衛生**：使用中の結論の引用に証拠の層と口径が付いているかを定期的に抽出検査する。「答えていない」を「除外済み」と書く類の文型が見つかれば、事故として登記し、引用箇所をすべて改める。
- **メカニズム自体の版**：本フレームワークの文書には版番号と変更記録がある。「ずっとこうやってきた」が文書の中に出所を見つけられないものは、存在しないものとみなす。

## 自己点検表（週に一度走らせる）

| 問い | 証拠 |
|---|---|
| 先週、起床一ラウンドを超えて受領漏れした成果物はあったか？ | チェッカーのログ |
| すべての継続プロセスのハートビートは間隔内か？ | タイムスタンプの抽出検査 |
| 六種の回復故障のテストはまだすべて緑か？ | テスト出力 |
| 先週の閉単の中に「判定できない」や空待ちはあったか？ | クレームボードの走査 |
| 根本要求の照合は行われたか？ドリフト項目はボードに入ったか？ | 毎日の一ページ＋状態表 |
| ローカルとリモートの HEAD は一致するか？ | リポジトリごとの照合記録 |
