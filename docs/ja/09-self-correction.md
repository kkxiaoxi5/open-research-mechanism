# 09 · 自己修正：チームが自らを改訂する条件

チームに不足しているのは、たいてい自己修正の*能力*ではない。修正が安く、速く、安全であるような条件のほうである。チームがある午後から突然猛烈に自己改訂を始めたとしたら、その原因はメンバーがその午後に賢くなったことではほぼ決してない。原因は、修正のコスト構造が変わったことである。本章はその条件に名前を与え、運ではなく設計として設置できるようにする。

## 速率の式

自己修正の速率 ≈ **標準の明確さ × フィードバックの頻度 ×（1 ÷ 認めるコスト）× 改訂のライセンス**。各因子は設計変数である：

- 標準が過去の何百もの指示に散らばっていれば、照らし合わせる固定物がなく、修正は主人の注意と気分を待つことになる。
- フィードバックが週に一度来るなら、チームがどれほど有能でも修正は週に一度しか起きない。
- 誤りを認めることが人への告白を意味するなら、それは高くつき稀になる；書かれた文書への不適合の記録を意味するなら、安く頻繁になる。
- 途中の改訂が漂移や一貫性の欠如として罰せられるなら、合理的な代理は改訂を避ける。改訂が明示的にライセンスされる——先に作り、後で調整し、段階を踏む——なら、チーム本来の反復速度が現れる。

## 六つの条件

1. **強制の痕跡フォーマット。** すべての交付ブロックは三行を持つ：事前の予測、結果、どの判断が変わったか。誤りは当日のうちに、通常業務の副産物として、書面で表面化する——後から引き出される告白としてではない。監査も反思も、読む痕跡の質で決まる；この形式こそが、誰かが探しに行く前に証拠をテーブルの上に置く。
2. **書かれた、引用可能な標準。** 主人の枠組みは一つの権威あるページとして存在する（第01章の根本要求）。反思とは、そのページとの比較である。修正は「規則 X、範囲 Y、未遵守」として記録される——ライバルへではなく、文書へ頭を下げる。
3. **外部の監査チャネル。** 内部の者は自分の盲区を見られない；欠けた仕事の層の診断は、一般に外から来る。常設の外部レビュアーが、レビュアー自身の好みではなく主人の標準に照らして仕事を監査する——固定した周期で、すべての所見に証拠（コミット、チケット、ファイル）を付けて。このチャネルの価値は外部性と周期にある：時折の高頻度フィードバックの爆発を、恒常的な制度に変える。
4. **トリガー。反思は自己発火しないからである。** 有能な統括者は、*問われれば*確実に証拠を整理する；だが作業の途中で自ら止まり、その仕事がまだやる価値があるかを自問することは確実にはしない。だから問いは性格に任せず制度化する：毎日のページは一行の常設欄を持つ——**「今日私は何を定め誤ったか、誰がそれを止めたか」**——毎日答え、なければ「なし」と書く。「誰が止めたか」の半分が要である：それは復核者への功績を記録し、見られることこそが差し止めの行動を生かし続ける。
5. **段階を踏む反復のライセンス。** 主人は書面で述べる：チームは細部がすべて承認される前に作ってよく、後で調整してよく、大きな変更は段階を踏む（草稿 → 固定したテスト群で検証 → その後に初めて現行の入口を置換）。このライセンスが反復と漂移を分ける：それがなければ fault になる急速な改訂が、それがあれば服従になる。
6. **位置を特定できる誤り。** 規則は明示の適用範囲を持ち（「この門は層 A のみを管す」）、所見は座標を引く。全体的な非難（「漂移している」）は防御を生む；座標の正確な誤り（「この規則は範囲外で引用された」）は一時間以内の修正を生む。

## 二つの冷水条項

- **流暢な反思は成果ではない。** 反思のたびに、各項目を効果の状態つきで記帳せよ：効果が見える、まだ、あるいは一度だけ発火。その反思が何かを*直した*かどうかの判定は、反思自身ではなく、予定された対账（照合）に属する。滑らかな自己批判は安く作れて、何も証明しない。
- **自己報告は再構成であって内省ではない。** 代理が「なぜ良くなったか」を語る説明は、事後に記録から組み立てられたもので、内部からは検証できない。ゆえにこの仕組みは、自己の透明性よりも痕跡（条件 1）を信じる：自己報告が間違っていても記録が真実を示すように設計せよ。

## 仕組み自体の失敗様式

- **「なし」の連続。** 毎日の行に「なし」が長く続くのは、トロフィーではなく信号である：本当に誤りがなかったか、盲区が戻ってきたかのどちらかである。その行を復核者のログと照合せよ；乖離があれば、修理すべきはチームではなく痕跡フォーマットである。
- **監査の腐敗。** 外部チャネルが証拠の引用ではなく印象を報告し始めたら、その所見は受け入れが安くなくなり、修正は再び遅くなる。チャネルもチームと同じ痕跡規律に従う。
- **ライセンスの腐敗。** 反復のライセンスは、改訂が一度罰せられるたびに静かに失効する。最初に罰せられた改訂の後に明示的に更新せよ——さもなければ速率の式は旧い値へ崩れ戻り、「チームがまた悪くなった」ように見えるだろう。実際には条件が撤回されただけなのに。
