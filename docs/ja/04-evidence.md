# 04 · 証拠規律

この規律の目的は研究を遅くすることではなく、**結論が引用されるときに自らの重さを知っている**ようにすることである。

## 証拠の層（引用時は層を必ず付ける）

| 層 | 意味 | 引用ルール |
|---|---|---|
| 数学 | 明記されたモデルクラスの内部で証明／推論された結論 | モデルクラスの境界を必ず付ける。現実へ外挿しない |
| 合成 | 人造データ／偽市場で検証されたもの | 効果量は設定値であり、現実の推定ではない |
| 実装 | コードと口径が独立審査を受け、既知答えテストに合格したもの | 数字を引用できる。版を付ける |
| 現実統計・探索 | 方向を見たことのあるデータで得た記述 | 「記述」とのみ呼べ、「確認」とは呼べない |
| 現実統計・確認 | 未暴露データまたは真の前方記録で、事前登録に従って判定したもの | 「確認」と呼べる。検出力と口径を付ける |
| 実行 | 約定、コスト、スリッページ等が実際に測定されたもの | 測定されていないコストはすべて「仮定」と表示する |

## 五つの硬いルール

1. **事前の検出力が先**：平均を見る前に、検出可能な最小効果を計算する（MDE ≈ 2.8 × SE。事象が群れる場合はクラスタ化後の分散を使う）。MDE が予測効果より大きい → 確認作業は開始しない。探索は続けられるが、結論の強さは「記述」が上限となる。
2. **グローバル試行カウントは増えるのみ**：すべての試行（失敗、セッション変更、リポジトリ変更を含む）を同じ台帳に記録する。環境を変えても選択の履歴はリセットされない。有意性を報告するときは、グローバル N のもとの口径を示す。
3. **暴露登記**：すべてのデータに暴露状態（未見／方向を見た／開封済み）を表示する。「開封済み」の区間は確認に再利用できない。確認は未暴露区間か真の前方記録からのみ得られる。
4. **方向を見た印**：方向を見たことのあるデータの上で行った新しい設計は、成果物上に必ずその旨を表示し、その結果を確認に格上げしてはならない——このルールが防ぐのは市場ではなく自分自身である。
5. **収縮校正**：過去のペア（開発区間 vs 確認区間）からプロジェクトの収縮係数を推定し、事前の検出力計算では予測効果にまず収縮係数を掛ける。良い知らせだけを選んで報告された数字は、すべて収縮後の値で引用する。

## 既知答えと「壊したら必ず失敗」

- 新しいコードは、実データに触れる前にまず**既知答え**（手で計算できる小さな例）を通す。
- 主要モジュールごとに**壊したら必ず失敗**するテストを備える：一か所をわざと間違えると、テストは赤にならなければならない。赤にならないテストはテストではない。ラインをまたぐ変異請求書は、有効な同僚審査の形である。

## 前方記録

- 歴史的な試験問題を使い尽くした後、確認の唯一の源は**真の前方**である：事象の定義、データ取得時刻、採点ルールを事前に登記し、日ごとに着地させ、タイムスタンプを残し、採点は作者以外が行う。
- 前方経路には**指名された保守者**と着地チェックが必須である。保守者がいなければ「未開始」と書き、「記録の計画」を「記録中」と書いてはならない。
- 前方記録の確認周期は事象の数で数え、カレンダーで催促しない。検出力の計算に何件の事象が必要かは、登記ページに書く。

## コストと実行の口径

- バックテストの口径（手数料、スリッページ、約定の仮定）はプロジェクト所有者が版管理し、変更時は再実行して版を表示する。
- コストが実測される前は、結論の引用に「コストは仮定」のラベルを必ず付ける。コストに敏感な結論（純／粗の比が 1 に近いもの）は別に列挙し、実測口径が届いたら優先的に再審査する。

## 引用の禁区（書き方のレベルでの自己欺瞞防止）

締めくくりと報告で禁止される文型（参考リスト、プロジェクトごとに補充する）：

- 「答えていない」を「除外済み」と書くこと、「検出されなかった」を「存在しない」と書くこと。
- 探索層の記述数字で確認層の結論を支えること。
- 口径（取引ごと／クラスタごと、粗／純、どの区間のデータか）の表示されていない数字を引用すること。
- 「やる計画」を「やっている」と書くこと、「既読」を「受領済み」と書くこと。
